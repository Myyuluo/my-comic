# 04: 封面 URL 失败驱动自动续签

**What to build:** 封面加载失败（403、签名过期、5xx、解码失败）且 Source 可用时，应用自动做一次详情-only 刷新，落库新的 `series.coverUrl`、刷新持久字节并让书架立即重算；通过节流避免坏 Source 被反复请求。

**Blocked by:** 01（书架封面缓存写入后立即刷新）

**Status:** ready-for-agent

- [ ] 封面字节获取失败且 Source 已安装/启用时，触发一次详情-only 刷新；不要求章节列表刷新成功。
- [ ] 刷新成功时持久化新的系列描述与 `series.coverUrl`，保留旧章节列表（章节为空/失败不清空），刷新持久字节，并通过 ticket 01 的 revision/invalidation 让书架立即显示。
- [ ] 每本书每次应用启动最多自动续签一次，并有 24 小时冷却；冷却期内不重复请求。
- [ ] Source 未安装/停用、平台不支持或网络不可用时跳过自动续签，使用本地/生成封面或占位。
- [ ] 自动续签失败时保留旧缓存/占位，不删除已有封面字节，不进入重试循环，记录日志。
- [ ] 手动「刷新漫画」与 24 小时更新探针的既有行为保持不变；自动续签是额外的失败驱动恢复路径。
- [ ] 切换 URL 后旧的失败图片缓存不会继续压制新封面。
- [ ] 测试覆盖：旧 URL 403 → 详情返回新 URL → 落库/字节/书架更新；章节失败但封面落库；冷却不重复；源缺失跳过；连续失败不循环。
- [ ] 按 ADR 0023 记录自动续签/节流策略；不新增数据库 schema。
