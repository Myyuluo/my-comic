# 漫画书架弹窗、标签与备份改进（manga-ux-backup-batch）

Status: ready-for-agent
Date: 2026-11-09

## Problem Statement

漫画读者目前在四个地方遇到摩擦：

1. 把 Manga 移出 Library 时，不同入口给出不同确认体验：书架选择模式的批量删除、书架单卡的删除、在线 Manga 作品页共用带粉/蓝说明块与「记住这些选择」的重型弹窗；本地 Manga 作品页只有一个普通确认框；本地图源页的批量移出甚至没有确认。读者无法预期哪些数据会被删除，也无法每次单独决定是否删除本地文件与阅读统计。
2. 把 Manga 加入 Library 时没有标签选择步骤：读者必须先加入书架，再去书架批量打标签；而「书架」页签只显示没有标签的 Manga，后补标签会让作品从书架页签消失，操作割裂。
3. 设置「存储与下载」里存在不准确或不一致的文案：「孤儿阅读记录」把无归属的阅读记录当成用户概念；「导入 Mihon 备份 / 导出 Mihon 备份」的命名与 MyComic 自己的备份能力不符。
4. MyComic 目前只能导入 `.tachibk`，不能创建备份；而当前导入会跳过未加入 Library 但已读的作品、应用设置和标签。读者无法把自己的 Library、阅读进度、History、Tag、设置与 Source 配置完整迁移到另一台设备或 Mihon。

## Solution

- 统一所有「移出漫画书架」入口的确认弹窗：单一文案与结构，移除粉/蓝说明块、「记住这些选择」与同步提示；每次提供两个默认不勾选的选项：同时删除本地文件、同时删除统计数据。Local source 的原始文件也可以由读者显式勾选删除；文件删除先于数据库删除，失败时保留该 Manga 并报告。
- 在三个显式「加入书架」入口前插入标签选择：在线 Manga 作品页、本地 Manga 作品页、Local source 页批量加入。读者已有 Tag 时弹出选择器；没有 Tag 时直接加入。可以选多个 Tag，也可以一个都不选；点「完成」才入架，关闭弹窗即取消本次加入。静默加入与非 UI 批量路径保持无弹窗、未打标签。
- 修正设置页文案：清除数据库不再出现「孤儿」；「导入 Mihon 备份」改为「导入备份」并更新副标题；「导出 Mihon 备份」改为「创建备份」，启用后进入按 Mihon v0.21.3 参考布局的创建备份页。
- 实现完整的 `.tachibk` 导出并补齐导入：导出覆盖书架作品、章节、追踪记录、History、分类（映射自 Tag）、所有已读作品、应用设置、插件商店、图源设置与敏感设置；导入把 Mihon 分类恢复为 Tag、读回 MyComic 自己的应用设置与未入书架已读作品的 History。文件仍可被 Mihon v0.21.3 正常导入。

## User Stories

### 移出书架弹窗

1. 作为漫画读者，我希望从在线 Manga 作品页移出书架时看到统一的确认弹窗，以便清楚知道本次会删除什么。
2. 作为漫画读者，我希望从本地 Manga 作品页移出书架时看到同一个弹窗，以便两个来源的体验一致。
3. 作为漫画读者，我希望书架选择模式的批量删除使用同一个弹窗，以便批量操作也有完整的确认。
4. 作为漫画读者，我希望书架单卡长按菜单的删除使用同一个弹窗，以便单本删除与批量删除一致。
5. 作为漫画读者，我希望 Local source 页选择模式的批量移出也使用同一个弹窗，以便不会无确认地移出书架。
6. 作为漫画读者，我希望弹窗只保留标题、说明、两个勾选项与取消/删除按钮，以便界面干净、重点明确。
7. 作为漫画读者，我希望不再看到粉色的「会被删除」块，以便弹窗不重复堆叠信息。
8. 作为漫画读者，我希望不再看到蓝色的「会被保留」块，以便弹窗不再冗长。
9. 作为漫画读者，我希望不再看到「记住这些选择」，以便每次都由我重新决定。
10. 作为漫画读者，我希望不再看到「未配置同步」提示，以便不出现本应用没有的能力。
11. 作为漫画读者，我希望「同时删除本地文件」每次都默认不勾选，以便不会因为上次的选择误删。
12. 作为漫画读者，我希望「同时删除统计数据」每次都默认不勾选，以便不会因为上次的选择误删。
13. 作为漫画读者，我希望弹窗标题为「移出漫画书架」，以便动作与文案一致。
14. 作为漫画读者，我希望单本移出的说明为「把这部作品移出书架？阅读进度与已读标记会一并删除。」，以便知道固定会删除的内容。
15. 作为漫画读者，我希望批量移出的说明包含选中的作品数量，以便确认选择范围。
16. 作为漫画读者，我希望勾选「同时删除本地文件」后，在线 Manga 的已下载章节文件从本机删除，以便释放磁盘空间。
17. 作为漫画读者，我希望勾选「同时删除本地文件」后，本地 Manga 在 Local source root 中的原作文件夹或文件也一并删除，以便在弹窗内完成彻底清理。
18. 作为漫画读者，我希望批量混合选择在线与本地 Manga 时，勾选删除文件会同时处理在线已下载章节与本地原作文件，以便一次清理干净。
19. 作为漫画读者，我希望文件删除发生在数据库删除之前，以便删除失败时不会留下“书架里没有、文件还在”的中间状态。
20. 作为漫画读者，我希望某个作品的文件删除失败时，该作品仍留在 Library 并得到失败提示，以便稍后重试。
21. 作为漫画读者，我希望文件本来就不存在时视为已删除，以便不会因为历史残留文件卡住移出。
22. 作为漫画读者，我希望勾选「同时删除统计数据」后，该作品的阅读统计从统计中移除，以便不再计入阅读时长与页数。
23. 作为漫画读者，我希望本地 Manga 也能删除统计数据，以便两种来源的统计清理能力一致。
24. 作为漫画读者，我希望不勾选任何可选项时只移出书架，不删除本地文件与统计数据，以便默认行为安全。
25. 作为漫画读者，我希望取消按钮不改变任何数据，以便误触弹窗不会产生副作用。
26. 作为漫画读者，我希望移出书架仍然删除阅读进度、章节已读标记与 Tag 分配，以便移除是完整的 Library 动作。
27. 作为漫画读者，我希望移出书架不删除 History，以便书架状态与阅读历史互不干扰。
28. 作为漫画读者，我希望在线 Manga 移出前先停止排队中与下载中的任务，以便不会继续下载一个已移出的作品。
29. 作为漫画读者，我希望独立的「删除本地文件」菜单动作继续存在，以便不经过移出书架也能直接删除本地文件。
30. 作为漫画读者，我希望批量删除时被当前筛选隐藏的选中项继续被提示，以便知道哪些项本次不会处理。

### 加入书架前选择标签

31. 作为漫画读者，当我已创建 Tag 时，从在线 Manga 作品页点「加入书架」应先看到标签选择弹窗，以便加入时顺手归类。
32. 作为漫画读者，当我已创建 Tag 时，从本地 Manga 作品页点「加入书架」应先看到同一个标签选择弹窗，以便两种来源一致。
33. 作为漫画读者，当我已创建 Tag 时，从 Local source 页批量加入书架应只弹一次标签选择，以便批量归类。
34. 作为漫画读者，当我还没有创建任何 Tag 时，点「加入书架」应直接加入，不弹标签选择，以便新用户没有多余步骤。
35. 作为漫画读者，我希望标签选择弹窗标题为「标签」，副标题显示本次要加入的作品数量，以便知道正在处理多少部作品。
36. 作为漫画读者，我希望标签可以多选，以便一部 Manga 同时属于多个标签。
37. 作为漫画读者，我希望一个 Tag 都不选也能点「完成」，以便按未打标签加入「书架」页签。
38. 作为漫画读者，我希望只有点「完成」才执行加入，以便确认操作。
39. 作为漫画读者，我希望点弹窗外部、按 Esc 或关闭弹窗等于取消本次加入，以便不会意外加入。
40. 作为漫画读者，我希望在弹窗里搜索 Tag，以便在标签很多时快速找到。
41. 作为漫画读者，我希望在弹窗里直接新建 Tag，以便加入时就完成归类。
42. 作为漫画读者，我希望批量加入时同一组 Tag 应用到本批所有新加入的作品，以便批量整理。
43. 作为漫画读者，我希望批量选中里已经在 Library 的作品不被重新加入，也不被本次 Tag 选择影响，以便不改变既有归属。
44. 作为漫画读者，我希望从 Local source 重新加入已移出书架的作品时也能选 Tag，以便恢复时直接归类。
45. 作为漫画读者，我希望加入时打上的 Tag 立即生效，作品出现在对应标签页签而不是「书架」页签，以便与现有页签规则一致。
46. 作为漫画读者，我希望点开未入架作品的章节时仍静默加入 Library，不弹标签选择，以便阅读不被打断。
47. 作为漫画读者，我希望静默加入的作品保持未打标签，以便出现在「书架」页签。
48. 作为漫画读者，我希望拖拽导入、批量导入、重建下载索引、远程接管与 CLI/API 加入保持现有行为，不弹标签选择，以便批量流程不被逐个弹窗打断。
49. 作为漫画读者，我希望取消标签选择时不会写入任何 Tag 分配，以便不会留下孤儿标签记录。
50. 作为漫画读者，我希望加入失败时不会写入 Tag 分配，以便数据保持一致。

60. 作为漫画读者，我希望「创建备份」是一个独立页面，以便有足够空间选择导出内容。
61. 作为漫画读者，我希望页面分为「书架」与「设置」两组卡片，与 Mihon 的参考布局一致，以便迁移时一眼看懂。
62. 作为漫画读者，我希望「书架」组包含：书架中的作品、章节、进度记录、历史、分类、所有已读作品，以便按需选择。
63. 作为漫画读者，我希望「设置」组包含：应用设置、插件商店、图源设置、包含敏感设置，以便按需选择。
64. 作为漫画读者，我希望所有勾选项默认勾选，敏感设置默认不勾选，以便默认导出完整且不泄露凭据。

68. 作为漫画读者，我希望「包含敏感设置」只有在应用设置或图源设置勾选时才可用，以便与 Mihon 的规则一致。
69. 作为漫画读者，我希望勾选「书架中的作品」时导出 Library 中的全部 Manga 及其书架信息，以便迁移书架。
70. 作为漫画读者，我希望勾选「章节」时导出每部 Manga 的章节列表，以便 Mihon 恢复后能继续阅读。
71. 作为漫画读者，我希望勾选「进度记录」时导出外部追踪记录（当前仅 Bangumi），以便追踪平台上的进度不丢。

74. 作为漫画读者，我希望勾选「所有已读作品」时，未加入 Library 但有阅读记录的作品也进入备份，以便完整保留阅读记录。

## Implementation Decisions

### 移出书架

- 所有「移出书架」入口共用一个确认弹窗：书架选择模式批量、书架单卡菜单、在线 Manga 作品页、本地 Manga 作品页、Local source 页选择模式批量。独立的「删除本地文件」动作保留自己的确认框，不与移出弹窗合并。
- 弹窗结构：标题「移出漫画书架」；单本说明「把这部作品移出书架？阅读进度与已读标记会一并删除。」；批量说明「确定把选中的 N 部作品移出书架？阅读进度与已读标记会一并删除。」；两个勾选项；取消与危险样式的删除按钮。
- 删除粉/蓝说明块、「记住这些选择」与「未配置同步」提示；不显示「从所有设备删除」。
- 两个勾选项默认不勾选，每次打开都重新从默认值开始。移除 `delete_prompt_remembered_choices` 偏好及其读写；旧值忽略，不做迁移。
- 「同时删除本地文件」对所有来源显示。在线 Manga 删除 Download library 中的已下载章节文件；本地 Manga 删除 Local source root 中的原作文件夹或文件。按用户决定，文案统一使用「已下载的章节文件会从本机删除，且无法恢复。」，不按来源类型改写。
- 「同时删除统计数据」对所有来源可用，副标题为「该作品的阅读时长、页数与查词/制卡计数将从统计中移除，且无法恢复。」；批量时使用「所选作品的……」。
- 删除顺序：先停止并取消该作品的下载任务，再尝试删除本地文件，成功后删除数据库条目。文件删除失败时保留该作品在 Library，并在结果中报告失败；文件不存在视为删除成功。
- 批量删除逐作品独立处理：部分成功时报告成功/失败数量；被筛选隐藏的选中项继续按现有提示处理，不参与本次删除。
- 移出书架固定删除 Library 条目、Reading progress、Chapter 已读标记、Tag 分配与下载索引；不删除 History。
- 统计数据删除覆盖阅读统计主记录、旧统计投影与查词/制卡计数，并写入统计墓碑，避免其他路径把已删统计加回。

### 加入书架前选标签

- 仅三个显式入口弹标签选择：在线 Manga 作品页「加入书架」、本地 Manga 作品页「加入书架」、Local source 页选择模式批量「加入书架」。
- 弹窗仅在用户至少有一个 Tag 时出现；零 Tag 时直接加入。已有 Tag 的判断是全局 Tag 数量大于零，不是当前作品是否已有 Tag。
- 复用现有标签选择器的视觉与交互：标题「标签」、副标题「N 个条目」（N 为本次加入的作品数）、搜索、全部标签、Tag chips、新建标签、完成。即使批量加入也使用「完成」，不使用「应用/取消」双按钮。
- 增加“延迟写入”模式：选择器只返回选中的 Tag 集合，不写数据库；加入服务在创建 Library 条目成功后统一写入 Tag 分配。取消或加入失败时不留下 Tag 分配。
- 多选；允许零选；零选时按未打标签加入，出现在「书架」页签。点「完成」执行加入；点外部、Esc 或关闭弹窗取消本次加入，不创建 Library 条目。
- 批量加入只弹一次，所选 Tag 应用到本批所有新加入的作品；已在 Library 的作品不重新加入、不应用本次 Tag。
- 从 Local source 重新加入已移出书架的作品同样经过上述流程。
- 静默加入路径保持不变：点开未入架作品的章节时先静默 Add to Library，不弹标签选择，保持未打标签。拖拽/批量导入、重建下载索引、远程接管、CLI/HTTP API 也不弹。
- 书架页签规则不变：带任意 Tag 的 Manga 不出现在「书架」页签，只在对应标签页签出现。

### 设置页文案

- 清除数据库副标题改为：「删除全部历史、未入书架的作品记录与阅读记录；书架进度、下载与本地图源都会保留。」
- 清除数据库进度步骤改为：「正在清理阅读记录」。
- 备份分组第一行：标题「导入备份」，副标题「本应用支持导入Mihon的备份文件，请选择您的.tachibk文件。」；文件选择框标题也改为「导入备份」。
- 备份分组第二行：标题「创建备份」，副标题「将书架数据导出为.tachibk文件。」；该行从禁用变为可用，点击进入创建备份页。
- 保留备份分组在「存储与下载」中的现有位置与顺序；其他语言按语义同步，中文以上述文案为准。

### 创建备份

- 新增独立的创建备份页：顶部标题「创建备份」，两组卡片「书架」「设置」，底部主按钮「创建」。复用现有设置页卡片、复选框与按钮样式，不引入新视觉语言。
- 书架组勾选项与顺序：书架中的作品、章节、进度记录、历史、分类、所有已读作品。设置组：应用设置、插件商店、图源设置、包含敏感设置。
- 默认全部勾选，包含敏感设置默认不勾选；每次打开恢复默认，不持久化选择。
- 依赖规则与 Mihon 一致：「书架中的作品」关闭时，章节、进度记录、历史、所有已读作品置灰；「包含敏感设置」仅在应用设置或图源设置勾选时可用。「分类」可以单独导出。
- 「创建」在没有任何可导出分组时置灰；可导出的判定至少包含书架中的作品、分类、应用设置、插件商店、图源设置之一。
- 导出格式：gzip 压缩的 protobuf，字段号严格对齐 Mihon v0.21.3。偏好值只使用六种标准类型：Int、Long、Float、String、Boolean、StringSet，并使用标准类型名（`IntPreferenceValue`、`LongPreferenceValue`、`FloatPreferenceValue`、`StringPreferenceValue`、`BooleanPreferenceValue`、`StringSetPreferenceValue`）。不使用自定义值类型，避免 Mihon 恢复失败。
- 书架中的作品：导出 Library 中的 Manga 为备份 Manga，包含 Source ID、作品 URL、标题、作者、画师、简介、Genre、状态、封面 URL、加入时间与 favorite=true。Source ID 与章节 URL 必须使用原值，不能重写。
- 章节：导出每部 Manga 的章节 URL、名称、Scanlator、read、bookmark、lastPageRead、dateFetch、dateUpload、chapterNumber 与 sourceOrder。章节已读与页内进度属于章节数据，由「章节」勾选项控制。
- 进度记录（UI 标签沿用参考图，实际为 Tracking）：导出 Bangumi 追踪记录；其他 tracker 当前没有存储，不导出。导出字段包含同步 ID、远端作品 ID、最后阅读章节、状态、评分、开始/完成时间等已有数据。
- 历史：每部 Manga 导出最近一条 History；字段为章节 URL、lastRead、readDuration。若章节未导出，Mihon 可能丢弃找不到章节 URL 的历史，这是格式本身的约束。
- 分类：每个 Tag 导出为 Mihon 分类，名称取 Tag 名称、order 取 Tag 排序；每部 Manga 的 categories 写入其 Tag 的 order 值。Tag 颜色不属于 Mihon 分类格式，不导出。
- 所有已读作品：从未加入 Library、但存在阅读 History 的在线作品导出为 favorite=false 的备份 Manga，包含快照中的 Source ID、作品 URL、标题、作者、封面与历史时间。若快照没有章节 URL，则只导出作品元数据，不伪造章节或 History 链接。
- 应用设置：导出 MyComic 自己的应用设置键值，不做 Mihon 键名映射；排除设备本地键与敏感键（当包含敏感设置未勾选时）。使用标准偏好值封装。Mihon 会安全保存不认识的键，不影响导入。
- 插件商店：只导出**漫画** Extension store 的 index URL、名称、badge、联系站点、签名 key、Discord、是否 legacy 与扩展列表 URL。MyComic 是漫画-only 应用，且 Mihon v0.21.3 的 `BackupExtensionStore` 没有 media-kind 字段，无法表达 Aniyomi（视频）store，因此不导出非漫画 store（见 ADR 0019 Amendment）。
- 图源设置：按 Source 导出配置，sourceKey 使用 Mihon 约定的 `source_<sourceId>`；跳过空的配置组与导入生成的不可用占位源。包含敏感设置未勾选时排除密码/Token 等敏感键。
- Source 列表：从本次导出的作品 Source ID 生成备份 Source 条目，名称取已知 Source 名称；用于 Mihon 在缺失扩展时展示来源名。
- 保存：点「创建」后弹出保存对话框，默认目录为 Backup directory；默认文件名 `my-comic_YYYY-MM-DD_HH-mm.tachibk`。写入临时文件，成功后移动到目标路径；失败时删除临时文件并报告。取消保存不写文件。
- 创建过程显示进度；完成后提示目标路径。不引入定时自动备份。
- 敏感设置的判定复用现有 `PrefRedactionPolicy` 语义；MyComic 没有 Mihon 的 `__PRIVATE_` 前缀约定，因此按现有敏感键集合与前缀/子串规则过滤。

### 导入补齐

- Mihon 分类导入改为 Tag：按名称查找或创建 Tag，按分类 order 设置 Tag 排序，按每部作品的分类 order 写入 Tag 分配。不再把分类写入隐藏合集；旧隐藏合集保留不动，不自动迁移。
- 导入 MyComic 生成的备份时，Tag 从标准分类字段恢复；不需要私有标记字段。
- 应用设置：只导入 MyComic 已知的应用设置键，跳过 Mihon 原生键；只补齐本机缺失的键，不覆盖已有值。标准偏好值类型全部支持；未知类型按现有行为报错并中止，避免半导入。
- 未入书架已读作品：favorite=false 的作品不创建 Library 条目；恢复其 History 行（作品快照、标题、封面、最近阅读时间、可用的章节 URL 与阅读时长）。
- 其余导入语义保持现有 Merge 行为：按 (Source, 作品 URL) 去重；章节并集；阅读进度取最大值；History 取较新；Extension store 按 index URL 合并；Source 配置按 (package, sourceId, key) 合并。
- 导入汇总报告增加 Tag、应用设置、未入架 History 的计数与跳过原因。
- 不提供覆盖/替换模式，不提供导入分节选择界面。

### 基线与文档

- 新功能基于 `integration/manga-ux-batch` 的当前提交开发，新开功能分支；不直接修改该集成分支。
- 功能分支的第一个本地提交包含本 spec 与 tickets，作为本地 git 存档点；现有 worktree 中未提交的生成文件不纳入历史。
- 更新 `GLOSSARY.md`：Remove from Library 明确本地文件可在显式勾选后删除；Category 明确与 Tag 的双向备份映射；Backup/Export 明确 MyComic 可以生成 `.tachibk`；新增或澄清 Reading statistics。
- 新增 ADR：记录 `.tachibk` 导出、标签/分类映射、应用设置键策略与导入补齐边界。
- 更新 ADR 0005：导出从“计划中”改为本次交付；导入语义增补。

## Testing Decisions

- 好测试只断言用户可见行为与数据结果，不测试私有方法、widget 结构或实现细节。页面级测试挂载真实页面，使用真实数据库、真实偏好库与可控的 Source/下载服务；备份测试使用合成 fixture 与真实数据库。
- 只使用两个现有测试 seam，不新增更低层或更高层 seam：
  1. 页面级 widget/集成测试 seam：真实数据库 + 可控 Source/下载服务 + 真实偏好库。用于移出弹窗、标签选择、设置页文案与创建备份页。
  2. 备份 fixture/parser/import-service seam：使用现有合成 `.tachibk` fixture 构建器、解析器与导入服务，加上真实数据库。用于导出 → 导入往返与 Mihon 格式兼容。
- 文件删除测试使用临时目录，不触碰真实 `local` 或 Download library。
- 覆盖模块：
  - 移出书架：五个入口的弹窗内容一致；默认不勾选；删除文件与统计的组合；本地图源文件删除；批量混合选择；文件删除失败保留作品；文件缺失视为删除；取消无副作用；History 保留；记住选择偏好不再生效。
  - 加入书架 × 标签：在线/本地/批量三个入口；有 Tag 与零 Tag；多选与零选；完成后入架并写 Tag；关闭弹窗取消；批量同一组 Tag；已在 Library 的作品不受影响；静默加入无弹窗且未打标签；取消不写 Tag。
  - 设置页：清除数据库两处文案；导入/创建备份标题与副标题；创建备份行可用并进入页面。
  - 创建备份：页面布局与两组勾选项；默认值与重置；依赖规则与创建按钮禁用；每个勾选项的导出内容；敏感设置过滤；保存目录与文件名；进度与成功/失败提示；无残留半成品文件。
  - 备份往返：MyComic 导出 → 解析 → 导入后 Library、章节、阅读进度、History、Tag、应用设置、插件商店、图源设置一致；Mihon 原生备份导入后分类变 Tag；未入架已读作品恢复 History；重复导入幂等；未知偏好值类型报错且不写入。
  - 格式兼容：字段号、标准偏好值类型、分类 order 引用、Source ID 与章节 URL 原值、favorite=false 行为。
- Prior art：现有书架页面级测试（多选、标签筛选、删除确认）、标签选择器测试、`settings_downloads_open_page_subtitle_guard_test`、`mihon_backup_parser_test`、`mihon_backup_import_test`、`mihon_backup_fixture`、`backup_directory_test`。
- 手动验证使用项目根目录的两份真实 Mihon 备份（小样本与 8,634 部作品的大样本），只在本地读取，不提交、不纳入自动化 fixture。

## Out of Scope

- 把 MyComic 应用设置的键名映射为 Mihon 的键名。
- 导入时的分节选择、覆盖/替换模式或恢复选项页。
- 定时自动备份。
- 把旧的隐藏合集自动迁移成 Tag。
- 移出书架时删除 History。
- 改变「书架」页签的归属规则。
- 改造独立的「删除本地文件」菜单动作。
- Bangumi 之外的 Tracking provider。
- 下载或补全备份中的封面图片。
- 设备间实时同步。
- 非漫画模块或不可达页面的删除弹窗改造。
- 在仓库中提交真实 `.tachibk` 文件或把真实备份用作自动化 fixture。

## Further Notes

- 第 3 项是事实确认，不需要改动：「程序数据位置」是 Program state root，默认 exe 同级的 `userdata`（不可写时回退 `%LOCALAPPDATA%\MyComic\userdata`），保存数据库、应用偏好、扩展与扩展登录态、字体、WebView 数据、日志、更新包与可再生缓存；下载、本地漫画与备份在「存储位置」（Content root），不在这个目录。
- 参考图里的「进度记录」实际对应 Mihon 的 Tracking（外部追踪记录），不是 Reading progress；为了避免界面与参考图不一致，UI 标签仍用「进度记录」，领域文档中说明其真实含义。
- 参考图里的「分类」在 MyComic 中由 Tag 承载：导出时 Tag → Mihon 分类，导入时 Mihon 分类 → Tag。「书架」页签等价于 Mihon 的 Default 分类。
- 本地图源勾选删除文件时沿用在线文案，这是用户明确选择的结果；实现与测试按统一文案验证。
- 两次 UI 改动（统一移出弹窗、创建备份页）是用户逐项批准的，仍受 ADR 0008 约束：复用 Fushi v3.0.0 的组件、主题与布局语言，不引入新视觉体系。
- 用户提供了两份真实 Mihon 备份用于本地往返验证；`*.tachibk` 已在 `.gitignore` 中，不提交。
- 新功能分支基于 `integration/manga-ux-batch`，第一个本地提交为 spec/tickets 存档点；出错时可回到该提交或原集成分支。
