# 漫画下载物化、清库关联与章节顺序（manga-download-materialization）

Status: ready-for-agent
Date: 2026-11-10

## Problem Statement

漫画读者在 `.tachibk` 导入、在线源阅读/下载、清除数据库与章节列表之间遇到一组相互关联的问题：

1. 打开在线源作品详情页、阅读或点击章节时，会在 `downloads/{source}/{manga}` 下提前生成目录和 `cover.jpg`；导入作品阅读后还会留下空目录；来源未安装时甚至生成以数字 sourceId 命名的目录。
2. 「清除数据库」只删记录，但重新打开同一作品后，已下载的本地文件无法通过批量操作删除，只能逐章用单章菜单删除；再次打开详情页还会生成 `{漫画名} (2)`、`(3)` 的重复目录。
3. 用户提供的本地 CBZ/文件夹（没有 `pages.json`）或根 manifest 单章作品，经「重建下载索引」后可以阅读，但章节列表仍显示「本章尚未下载」。
4. 章节多选批量栏只有标记已读/未读与删除下载，缺少「下载选中章节」。
5. 章节条目前的章节号胶囊在导入作品里与「第 N 话」标题重复。
6. 章节标题固定显示总章节数与数字徽章，不能反映「只看未读」与下载状态筛选后的可见数量。
7. `.tachibk` 导入作品的章节数组顺序与 App 的「最新在前」约定不一致：读完第 1 话会被当成最后一话，提示「已经是最新一章」，不会切到第 2 话。

「导入时不写入 History」的请求已由用户取消；History 导入与导出保持现状。

## Solution

- Download library 只在真正开始章节下载时才物化：作品页浏览、在线阅读、导入、重建索引都不创建空目录；封面完全退出 Download library，只由 Cache 提供。
- 来源未安装的导入作品不创建目录、不请求封面，显示灰封面；扩展安装后自动恢复封面；已有本地下载文件仍可阅读。
- 作品目录按 `pages.json` 身份复用；同一作品永不重复建目录，同一 Source 下同名不同作品共享一个目录（Mihon 做法）；重建/重链按每个章容器的身份归属，删除与空目录清理保护其他作品。
- 「清除数据库」继续保持只删记录；重新打开作品时按 `pages.json` 身份或容器名自动重建 `extractDir` 与章节映射，批量删除改用与单章删除相同的身份回退，不再依赖数据库映射或书架归属。
- 用户提供、没有 `pages.json` 的容器只要按身份或容器名与章节关联上，就视为已下载；`local` 根下的用户原件永不被删除。
- 多选批量栏新增「下载选中章节」，只入队可下载的选中章节。
- 去掉所有章节号胶囊；章节标题改为「共 X 章」，X 跟随「只看未读」与下载状态筛选。
- 导入时持久化 Mihon 的 `sourceOrder`，阅读器按 `sourceOrder` 构造独立的升序阅读列表；不再依赖 `chaptersJson` 数组顺序或显示顺序换章。

## User Stories

### Download library 物化与封面

1. 作为漫画读者，我希望打开在线源作品详情页时不创建 `downloads` 目录，以便浏览作品不会在磁盘上留下东西。
2. 作为漫画读者，我希望只阅读在线章节时不创建下载目录，以便在线直读不产生副作用。
3. 作为漫画读者，我希望只是查看导入作品详情时不创建目录，以便导入的书架保持干净。
4. 作为漫画读者，我希望只有真正开始下载章节时才创建 `downloads/{source}/{manga}` 目录，以便目录只代表实际下载。
5. 作为漫画读者，我希望阅读未下载的导入作品时不生成空目录，以便不再出现空文件夹。
6. 作为漫画读者，我希望下载完成后对应的 `source`/`manga` 目录存在，以便能在资源管理器里找到文件。
7. 作为漫画读者，我希望应用不再往下载目录写 `cover.jpg`，以便 Download library 只包含章节内容。
8. 作为漫画读者，我希望书架封面来自远程封面地址或 Cache，以便不需要封面文件也能看到封面。
9. 作为漫画读者，我希望详情页封面来自远程封面地址或 Cache，以便与书架一致。
10. 作为漫画读者，我希望清理缓存且离线时显示占位封面，以便能接受封面属于 Cache 的代价。
11. 作为漫画读者，我希望重新联网或重新打开后封面自动恢复，以便不影响长期使用。
12. 作为漫画读者，我希望已有的 `cover.jpg` 不被自动删除，以便不执行破坏性清理。
13. 作为漫画读者，我希望同一部作品复用已有目录，不再生成 `{漫画名} (2)`，以便清库后重开不会出现重复目录。
14. 作为漫画读者，我希望同一 Source 下标题完全相同的两部作品共用一个目录，以便与 Mihon 的目录习惯一致。
15. 作为漫画读者，我希望共享目录里的每一章仍按 `pages.json` 身份归属到正确作品，以便阅读、下载状态与删除不串作品。
16. 作为漫画读者，我希望删除作品 A 的下载不会影响共享目录里作品 B 的章节，以便共享目录安全。
17. 作为漫画读者，我希望只有目录不再被任何作品引用时才清理空目录，以便不会误删另一部作品的容器。
18. 作为漫画读者，我希望章名冲突时使用短哈希或扫译组后缀，而不是 `(2)`，以便文件名可区分且不出现重复编号。
19. 作为漫画读者，我希望应用不自动删除旧版本遗留的封面目录或随机字符串目录，以便清理动作保持显式。

### 来源未安装

20. 作为漫画读者，我希望来源未安装的导入作品不创建任何下载目录，以便不在 `downloads` 下生成数字 sourceId 目录。
21. 作为漫画读者，我希望来源未安装时不发起封面请求并显示灰封面，以便减少无谓的网络与磁盘动作。
22. 作为漫画读者，我希望来源未安装但本地已有下载文件时仍能阅读，以便离线内容不因缺少扩展而失效。
23. 作为漫画读者，我希望安装对应扩展后无需重新导入即可加载封面与读取来源章节，以便安装后立即恢复。
24. 作为漫画读者，我希望作品页保留「来源未安装」提示，以便知道为什么不能刷新或下载远程章节。
25. 作为漫画读者，我希望不再生成以数字 `sourceId` 命名的随机目录，以便目录名始终可读。
26. 作为漫画读者，我希望来源未安装时打开未下载章节仍给出明确提示且不创建文件，以便不会静默失败。

### 清除数据库与批量删除

27. 作为漫画读者，我希望「清除数据库」只删除数据库记录，不删除磁盘文件，以便下载内容仍然保留。
28. 作为漫画读者，我希望清库后重新打开同一作品时自动关联已有下载文件，以便不需要手动运行「重建下载索引」。
29. 作为漫画读者，我希望自动关联后章节列表显示「已下载」，以便状态与实际文件一致。
30. 作为漫画读者，我希望清库后仍能通过多选批量删除已下载章节，以便不用逐章操作。
31. 作为漫画读者，我希望批量删除与单章删除使用同一套身份回退，以便两条路径行为一致。
32. 作为漫画读者，我希望批量删除不依赖作品是否在书架、是否安装来源或是否有数据库映射，以便清库后仍然可用。
33. 作为漫画读者，我希望批量删除只作用于 `downloads` 管理的容器，以便不会删除 Local source 的用户原件。
34. 作为漫画读者，我希望批量删除只处理已下载章节，排队、下载中、暂停、失败与文件缺失的章节不参与，以便不会误删或空操作。
35. 作为漫画读者，我希望批量删除前有二次确认，以便避免误删。
36. 作为漫画读者，我希望删除后章节已读标记与阅读进度保留，以便删除文件不等于清空阅读记录。
37. 作为漫画读者，我希望删除最后一个章节后清理空的 manga 目录，并在整个 source 目录也空时清理 source 目录，以便不留下空文件夹。
38. 作为漫画读者，我希望单章作品的根 `pages.json` 章节删除时清空该作品的下载内容但保留作品条目与阅读进度，以便仍能重新下载。
39. 作为漫画读者，我希望批量删除后列表立即刷新为未下载，以便看到操作结果。

### 用户提供的本地文件

## Implementation Decisions

- **基线**：以 `integration/manga-library-membership` 为代码基线；实现完成后合并回该分支。
- **Download library 惰性物化**：创建/刷新非书架或书架 Manga 行时只写数据库，不创建目录、不拉取封面；阅读器打开章节不再调用会创建或重指目录的路径；目录只在章节下载任务真正开始时由下载服务创建。已有 `extractDir` 不在首次阅读时重指，避免导入行被改到空目录。
- **封面**：封面不属于 Download library。移除首次建行时的 `cover.jpg` 拉取与写入；书架与作品页按「显式本地封面 → 常规本地封面文件 → 远程 coverUrl / Cache → 占位封面」解析。已有封面文件保持原位，不做清理。
- **目录身份与共享目录**：作品目录解析先按 `pages.json` 的 Download identity（runtime + numeric sourceId + mangaKey；extensionPackage 做兼容/tie-breaker）匹配并复用；同一作品永不重复建目录。同一 Source 下不同作品标题相同则共用同一目录，与 Mihon 一致；不同身份不因同名而新建 `(2)`。章容器名冲突使用短哈希或扫译组后缀，不使用 `(2)`。
- **共享目录保护**：重建下载索引与导入后重链必须逐个章容器读取 `pages.json`，按身份把它映射到对应作品；不得把共享目录当成单一身份整目录跳过。删除下载只删除目标作品自己的映射容器；空目录清理前检查该目录是否仍被其他作品引用。删除与清理只作用于 `downloads`，永不删除 `local` 原件。
- **来源未安装**：不创建目录、不请求封面、显示灰封面；已有本地容器仍按身份/名称关联并可阅读；安装扩展后由运行时解析来源并加载封面，无需重新导入或迁移身份。保留「来源未安装」提示与现有降级行为。
- **清除数据库**：保持只删记录（非书架作品行、章节映射、历史、阅读状态），不删文件。重新打开作品时按 `pages.json` 身份或容器名自动重建 `extractDir` 与 `manga_chapter_dirs`；不需要用户手动运行 Rebuild download index。
- **下载状态**：章节是否已下载由 Download index 的磁盘关联决定，与 Library membership、来源是否安装无关。按 `pages.json` 身份关联的容器、按容器名关联的无 manifest 容器、以及单章作品根目录的 `pages.json`/页负载，只要可读即视为已下载；无 manifest 容器不要求完整性检查通过 `pages.json` 校验。
- **批量删除**：批量删除复用单章删除已有的身份回退路径，不再只调用依赖数据库映射的删除接口；适用集合由列表的已下载状态决定，不要求 Manga 行存在。单章根 manifest 删除时清空该作品的下载负载并保留条目与阅读进度；目录空了且无人引用时删除目录。
- **批量下载选中章节**：批量栏在「标记未读」与「删除下载」之间新增下载动作。只把选中的、未下载、未排队/下载中、来源已安装且未锁定的在线章节交给现有下载 planner/enqueue；本地源、来源未安装或无适用项时动作置灰；混合选择只处理适用子集；不弹确认；沿用现有 CBZ 设置与下载顺序。
- **章节列表 UI**：停止渲染章节号胶囊（详情页与阅读器抽屉一致），保留 `chapter.number` 数据用于排序、去重与 Mihon 映射；多选勾选标记保留。章节标题改为「共 X 章」，X 为「只看未读」与下载状态筛选 AND 之后的可见章节数；空列表为「共 0 章」；排序不改变 X；移除单独的数字徽章，字体与布局沿用当前章节标题。
- **导入章节顺序**：备份导入时保存 `BackupChapter.sourceOrder`（proto field 10）到章节模型/JSON；在线源适配器为章节补 `sourceOrder = 列表下标`（0 = 最新）。阅读器单独构造阅读顺序列表：按 `sourceOrder` 降序（第 1 话→第 N 话），缺失时回退到章节号/上传日期；上一话/下一话为该列表的 `index ± 1`。作品页用同一批数据按 `sourceOrder` 升序（最新在前），切换「第一话在前」时反转。不得依赖 `chaptersJson` 数组顺序或显示顺序换章。
  - **已接受的导出偏差**：备份导出会写入标准的 Mihon 字段 `BackupChapter.sourceOrder`（`chapter.sourceOrder ?? 列表下标`），而不是保持导出代码完全不动。原因是 MyComic→MyComic 往返需要在重新导入后保留阅读顺序；在线条目的 `sourceOrder` 本来就是源列表下标，与 Mihon 导出同一字段的行为一致，Mihon 兼容性不受影响。其余导出行为不变（见 User Story 82）。
- **已有导入数据**：不实现旧数据方向猜测。已有导入作品通过重新导入同一 `.tachibk` 补齐 `sourceOrder`；导入幂等，不重复建作品。开发阶段按全新数据假设，不处理旧版遗留的封面目录/随机字符串目录。
- **不改变 History 导入/导出**：本批次不修改 `media_open_history` 的导入、导出或清除数据库语义。
- **Schema**：不新增数据库列/表；`sourceOrder` 存在章节 JSON/模型中。`chapterFlags`（Mihon 每作品排序方式）不在本批次导入，作品页继续使用现有全局「最新在前」偏好。

## Testing Decisions

- 好测试只验证外部行为：页面级测试驱动真实 UI 并断言可见文案、动作可用性、数据库行与临时 Content root 下的文件；服务级测试通过临时数据库与临时目录断言导入/重链/删除结果。不断言私有方法、内部调用次数或实现细节。
- 优先使用现有 seam，按高层优先：
  1. **Manga 作品页页面 harness（主 seam）**：覆盖打开详情不建目录/不写封面、来源未安装灰封面与无目录、章节标题「共 X 章」与筛选联动、章节号胶囊移除、多选批量下载的可用性与入队、清库后批量删除、空目录清理、共享目录的显示与状态。
  2. **备份导入服务 seam**：覆盖 `sourceOrder` 持久化、History 导入保持现状、重新导入幂等，以及导入作品章节顺序在作品页/阅读器中的表现。
  3. **Rebuild download index / DownloadLibraryIndex seam**：覆盖按 `pages.json` 身份与容器名关联、无 manifest 用户文件视为已下载、根 manifest 单章、共享目录逐章归属、批量/单章删除与空目录保护。
  4. **`resolveAdjacentMangaChapter` 纯函数 seam**：覆盖 `sourceOrder` 降序的阅读顺序、缺失时回退章节号/日期、上一话/下一话与「最新一章」边界。
- prior art：现有作品页多选/下载筛选/批量删除/下载状态/缺失来源/封面测试；备份导入测试；下载索引与重建索引测试；相邻章节纯函数测试；下载服务与 planner 测试。新测试沿用这些 harness 的临时数据库、临时 Content root 与 fake app model。
- 测试必须同时覆盖：新导入的 `.tachibk`、重新导入后的已有作品、在线源条目、来源未安装条目、无 manifest 的用户本地容器、单章根 manifest。

## Out of Scope

- History 导入/导出/清除语义的修改（用户已取消该请求）。
- 自动删除或迁移旧版本遗留的封面目录、随机字符串目录。
- 导入 Mihon 的每作品 `chapterFlags`/排序方式；本批次只使用 `sourceOrder` 与现有全局「最新在前」偏好。
- 离线封面持久化；封面只属于 Cache，离线或清缓存后显示占位封面。
- 删除 Local source 根下的用户原件。
- 新增下载引擎、调度器或下载格式；只复用现有下载服务、planner 与 CBZ 设置。
- 不重新导入即可自动修复已有导入作品的章节顺序。
- 超出「移除章节号胶囊」与「共 X 章」的 UI 重设计（受 ADR 0008 UI fidelity 约束）。
- 不同 Source 之间的同名目录共享；共享只发生在同一 Source 内。

## Further Notes

- 与 Mihon 对齐的依据：`BackupChapter.sourceOrder`（proto field 10）在恢复时写回数据库；`ReaderViewModel` 用 `getChapterSort(manga, sortDescending = false)` 单独构造升序阅读列表并取 `index ± 1`；默认按 source order 时，`sourceOrder` 0 为最新，阅读顺序即 `sourceOrder` 降序。当前导入丢弃了 `sourceOrder`，阅读器又假设 `chaptersJson` 为最新在前，导致读完第 1 话被当成最后一话。
- 共享目录是用户明确选择（Mihon 的 `DownloadProvider` 也只按 Source + 净化标题建目录并复用）；实现必须补上跨作品重链、删除与空目录清理保护，不能把共享目录当成单一身份。
- 领域文档：实现后更新 `GLOSSARY.md` 的 Download library、Cache、Clear database、Download index/下载状态、Source not installed 等条目；修订 ADR 0012（惰性物化、封面缓存、共享目录、清库重连）与 ADR 0019（来源未安装行为），并新增一篇记录「章节阅读顺序以 sourceOrder 为准」。
- 建议 ticket 拆分与顺序：
  1. 导入 `sourceOrder` 与阅读器阅读顺序、作品页排序。
  2. Download library 惰性物化与封面退出。
  3. 目录身份、同名共享目录、重建/删除保护。
  4. 清库后自动重链与批量删除。
  5. 无 manifest / 根 manifest 本地文件视为已下载。
  6. 批量下载选中章节。
  7. 章节号胶囊移除与「共 X 章」。
  8. 领域文档同步（GLOSSARY + ADR）。
- 实现顺序：1 → 2 → 3 → 4/5 → 6 → 7 → 8；每张 ticket 带页面级/服务级测试，最终运行 `flutter analyze` 与 Windows 构建。
