# 下载页只列可操作任务，暂停与继续全局化

下载页原先会永久保留已完成与已取消的任务行，也没有停顿整个队列的能力。我们决定把下载页收敛为「只列出此刻可操作的任务」，并让暂停 / 继续成为全局动作：

- 可见任务只有排队中、下载中、暂停与失败四种。
- 完成：任务从列表消失；下载文件与 Download library 映射保留，仍可阅读。数据库中的任务行也保留，作品页据此在文件缺失时仍能判断「文件缺失（Missing）」——章节列表可以区分「从未下载」与「下载过但文件没了」。
- 取消：任务行立即删除，并清理该任务的半成品（staging / 临时压缩包）；不保留「已取消」行，遗留的已取消行同样不再展示。
- 失败：任务保留在列表中，行内**同时**显示「重试」与「取消」（ticket 09）。重试沿用同一任务行复位并重跑；失败任务不自动重试，除非用户点「重试」或「全部继续」；全局暂停期间点「重试」只会让任务回到暂停等待，不会绕过暂停开跑。取消不弹二次确认，立即删除任务行并清理该任务的半成品（`.staging/<jobId>`、`{chapter}.cbz.tmp`、可能存在的映射容器），完成后 toast；其他任务不受影响。
- 暂停 / 恢复暂停只由下载页右下角的气泡胶囊按钮控制（失败行的「重试」是重试，不是暂停恢复）：列表为空时隐藏；列表非空且所有任务都是暂停或失败时显示「全部继续」；其余情况显示「全部暂停」。排队中 / 下载中 / 暂停 / 失败的任务行都可单独取消，但行内没有暂停 / 继续（失败行只有重试 + 取消两个动作）。
- 「暂停」是持久化的非终态：暂停运行中的任务会停止取页并保留已下载的部分，恢复后按页级续传继续；重启后暂停任务仍暂停；暂停期间新入队的章节直接以暂停入队，不会自动开始。「全部继续」把暂停任务恢复为排队，并重试全部失败任务。
- 单行暂停 / 继续曾纳入设计，后由用户明确撤销，只保留全局控制。

**Schema 迁移**：`manga_download_jobs.status` 是 TEXT 列，但表上有表级 `CHECK (status IN (...))`。SQLite 不支持原地放宽 CHECK，因此新增 `paused` 必须重建下载任务表，把 schema 从 v3 升到 v4：按同名列复制全部任务行并重建索引。升级现有库时会执行这次重建；更新版本创建的库仍由降级保护拒绝打开。规格原先假设「新增任务状态值不需要迁移」，实际不成立。

**Considered Options**

- **保留已完成 / 已取消行并提供清除操作（现状）**：列表会长期堆积已结束任务，正是用户要消除的噪音。
- **完成即删除任务行**：列表最干净，但会失去「下载过、文件后来没了」的 Missing 判定，章节列表无法区分从未下载与文件缺失。
- **单行暂停 / 继续**：控制更细，但用户已明确撤销；行内原有取消已占用操作位，再叠加暂停会让任务卡更拥挤，且全局按钮已覆盖主要诉求。
- **失败行只保留重试，取消收进「⋯」菜单**：行尾更省位置，但用户要求失败行同时看到「重试」与「取消」，藏进菜单会让「清掉失败队列」重新变成需要发现的动作。
- **暂停只存在内存里**：实现简单，但重启后暂停丢失，与用户「暂停状态在重启后保留」的要求冲突。
- **用现有状态值表达暂停**：避免 schema 迁移，但会重载 done / cancelled 等终态语义，误导任务领取、结束判定、备份与外部控制接口。
- **单独建暂停表或暂停列**：不改变状态 CHECK，但会让暂停状态出现第二个来源，worker 领取与全局按钮状态机都要跨两份数据判断。

**Consequences**

- 下载页不再提供已完成任务的浏览或清理界面；已完成文件仍保留并可阅读，清理入口留待未来的下载历史。
- 取消后不能在下载页看到「已取消」记录；重新下载需回到作品页发起。失败行的取消同样直接删行：清理完 staging / 临时包后 toast 确认，不保留失败记录。
- 失败行比其它状态多一个行尾动作（重试 + 取消两个圆形按钮）；共享任务卡的行尾操作从单个 `quickAction` 改为 `quickActions` 列表。
- 暂停不是终态：结束判定（已完成 / 失败 / 已取消）不能把暂停算进去；作品页的章节列表把暂停任务按「排队中」展示，恢复统一由下载页控制。
- 全局按钮状态由当前可见任务推导：逐行取消可能让按钮从「全部暂停」切到「全部继续」或隐藏。
- 新增 `paused` 值需要一次 v3→v4 的表重建；旧版本拒绝打开新库，避免不认识 `paused` 的 CHECK 拒绝写入。
- 已完成任务行默认保留在数据库中，作为 Missing 判定的依据；只有显式的清理操作（例如「清除已结束任务」）会删除它们。
