# 在线下载默认保存为 CBZ

在线章节原先只能保存为平铺图片文件夹，携带、备份与归档单章都不方便。我们决定把新开始的在线下载默认保存为 CBZ：

- 设置新增「保存为CBZ压缩包」开关，默认开启；升级用户首次见到时也是开启。
- 开启时章节载体为 `downloads/{source}/{manga}/{chapter}.cbz`；关闭时沿用同名文件夹。章节名净化、冲突后缀与路径截断规则两种形态共用。
- 压缩包根目录放平铺、零填充的页图与 `pages.json`，schema 与文件夹章节相同。
- 已有文件夹章节原样保留，不做批量转换；两种 Chapter container 共存。
- 数据库显式记录容器类型（folder / archive，schema v2→v3），已有行迁移为 folder；阅读、完整性检查、删除、页访问、缩略图、Rebuild download index 与互联读取都按容器类型分支。
- 下载仍先把页图写入 `.staging/{jobId}`（支持续传与页文件 `.tmp` 后改名），`pages.json` 最后写入 staging；随后在同一漫画目录生成 `{chapter}.cbz.tmp`，完成后原子改名为最终 `.cbz`。取消或崩溃只清理 staging 与未完成的临时包，不会留下可见的半成品。
- 格式在任务开始运行时确定：排队任务按真正开始那一刻的偏好值落盘，运行中的任务保持开始时的格式；下载任务表不持久化格式列。

**Considered Options**

- **继续只用文件夹（现状）**：实现最简单，但单章无法作为单文件携带、备份或归档，用户的原始痛点不解决。
- **批量把既有文件夹转换成 CBZ**：升级会改写用户文件，任务运行中转换还会产生竞态；收益只是形式统一，风险大于收益。
- **CBZ 作为可选、默认关闭**：对磁盘占用更保守，但大多数用户不会主动发现开关，无法达到「默认得到便于携带的单文件章节」的目标。
- **边下载边直接写最终 `.cbz`**：流式压缩更简单，但无法可靠续传，崩溃或取消会留下可见的半个压缩包。选定 staging → 临时包 → 原子改名。
- **在下载任务表保存格式列**：格式不是任务的持久属性；任务开始时读取一次偏好即可，避免历史任务因开关切换而语义漂移。

**Consequences**

- CBZ 的优势：单文件便于携带、备份与归档；目录中文件数更少；完成后一次性可见，删除即删一个文件。
- CBZ 的代价：资源管理器里不能直接翻看页图；页访问与缩略图需要按需解压到缓存；压缩期间需要与章节大小相当的额外临时空间；追加页或局部修复比文件夹困难。
- 文件夹的取舍：仍可直接翻看与手工整理，适合习惯文件管理器的用户；关闭开关即可继续使用。
- 混合库成为常态：所有消费章节载体的路径必须同时支持文件夹与压缩包；互联对端要么支持压缩包，要么显式跳过，不能留下会崩溃的分支。
- 取消下载不会留下半个 CBZ；最终压缩包只在完成时出现。
