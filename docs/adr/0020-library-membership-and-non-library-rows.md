# Manga 持久化与书架归属分离：非书架记录、非破坏移出与功能边界

用户反复在书架、非书架、下载与历史之间切换时，旧模型把「Manga 记录存在」等同于「在书架」：移出书架会删除记录与阅读状态，重新加入后阅读进度、下载索引与 History 断裂；从在线源阅读又会被静默加入书架。Mihon v0.21.3 的模型是非书架作品也持久化。我们决定引入 Library membership：

- 每个 Manga 记录带一个 Library membership 状态（存量数据迁移为在书架）。它是否在书架与它使用哪种阅读器无关；书架归属的唯一判据是 membership。
- 打开在线源作品页或从源阅读章节时，确保存在并复用一条非书架 Manga；阅读不再自动加入书架。Reading progress、Chapter 已读、History、Reading statistics 与下载都归属于这条记录，因此关闭应用后仍然保留。
- 显式加入书架把同一条记录的 membership 翻为在书架，不新建记录，不改变作品身份、阅读状态、下载目录或 History；记录尚不存在时才创建书架记录。加入时仍可选择 Tag，订阅入口随后出现。
- 移出书架默认非破坏：清除 membership、该作品的 Tag 分配与订阅/自动追更，保留 Manga/Chapter 记录、Reading progress、Chapter 已读、下载任务与索引、已下载文件与 History；之后重新加入复用同一条记录与同一个下载文件夹。
- 「同时删除本地文件」在在线 Manga 上删除已下载文件与下载索引，但保留非书架记录与阅读状态，之后可重新下载；在本地作品（Local source 或应用管理的本地卷）上删除本地文件后连记录与阅读状态一起删除，避免留下指向已删除文件的记录（History 仍保留）。「同时删除统计数据」两种作品都可选。文件删除失败时作品留在书架。不新增独立的「彻底删除漫画」动作。
- 非书架 Manga 可阅读、保存进度、继续阅读、标记已读/未读/此章及更早、批量标记、下载与删除下载、写 History 与统计、刷新章节、登录源与打开网站；其下载任务出现在下载页。它们不出现于书架、Home 继续阅读、Tag 页签与计数、更新探测、订阅/自动追更与备份的「书架中的作品」；不能分配 Tag、订阅或使用 Tracking。非书架作品下载完成后只提供可选的「加入书架？」提示，绝不自动加入。
- Local source 作品保持原有阅读习惯：尚未登记的本地作品在点开章节阅读时会静默登记为书架成员；显式移出后转为非书架记录，由本地图源页作为非书架作品展示。

**Considered Options**

- **保持「记录存在 = 在书架」**：改动最小，但移出必须删记录，阅读状态与下载索引无法保留，重新加入会重复建目录，正是本次要解决的问题。
- **为书架与非书架作品分别建表或维护两套身份**：边界清晰，但阅读器、History、下载与备份都要维护两套查找，容易产生重复记录。
- **在线源阅读继续自动加入书架**：能保证有记录承载状态，但违背「阅读不等于收藏」，用户的书架会被动塞满。
- **移出时提供独立的「彻底删除」动作**：表达更明确，但现有删除文件/统计数据选项已覆盖需求，新增动作会扩大误操作面。

**Consequences**

- 书架专属读取点必须显式按 Library membership 过滤；其余读取点（阅读器、Chapter 状态、History、下载与下载索引、重建、源页、导入去重）使用全部 Manga 记录。把「有记录」当作「在书架」会在加入 / 移出后造成计数、继续阅读或更新探测错误。
- 备份「书架中的作品」只导出书架成员；「所有已读作品」仍以 `favorite=false` 导出非书架已读作品（见 ADR 0019）。导入 `favorite=false` 条目会创建非书架记录（见 ADR 0005 / ADR 0019）。
- 移出后 History 仍可打开作品；非书架 Manga 没有 Home 继续阅读入口，用户通过 History 或来源作品页继续阅读。
- 本地图源无 manifest 的文件不按标题关联；非书架 Manga 与 Download index 共用 `pages.json` 的 Download identity 规则（见 ADR 0012）。
