# 一级导航固定为 Manga → 浏览 → 下载 → 设置，下载迁出浏览页

my-comic 的一级导航固定为 Manga → 浏览 → 下载 → 设置：Manga 与浏览两项常驻（旧模块开关、新手引导与 ctl 写入都不能隐藏或重排它们，平台 / 合规门禁仍然生效），下载是不绑定模块的一级页，固定跟在浏览之后；设置恒在最后，是全部模块关光后的安全回退面。下载任务列表从浏览页的「下载」视图页签迁出，成为这个一级页；浏览页只剩在线源 / 发现 / 导入三个视图页签。

下载页标题与浏览页一致（2026-11-07 用户要求，取代本 ADR 最初「固定展开」的形态）：使用页内浮动工具区里的标题胶囊，不显示任何视图页签；向下滚动收起、向上滚动或回到顶部重新显示，阈值与动画和浏览页共用同一套 `FushiFloatingChromeController` / `FushiFloatingChromeOverlay`。内容沿用现有的简单下载任务列表（`MangaDownloadTasksSection` 的漫画章节任务卡片与既有操作），没有任务时显示空态提示；页面保活，切走再回来保留滚动位置与任务订阅。刻意不启用仓库里现成但未接线的富任务浏览器（摘要 / 状态筛选 / 搜索 / 批量工具）。

旧下载视图的首张卡片被标题遮挡的根因是：列表只读取了外层浮动工具区留白（约 8px），没有计入浏览页标题栏自身高度（约 68px）。下载页改用页内浮动工具区后，列表在工具区**内部**用 `FushiFloatingChromeInsetSpacer` 读取运行时实测的顶边留白作为首项留白：首张任务卡片从标题下方开始，标题收起后列表内容继续上移，不留空白条。不得从工具区外层的 context 读取留白（那正是旧遮挡 bug 的读法）。

**Alternatives considered**

- 保留「下载」视图页签并修正其顶部留白：能修掉遮挡，但下载仍只有进入浏览页才能到达，与「一级目的地」的用户预期不符；也继续把下载状态绑在浏览页的页签控制器上。
- 给下载建一个真实 `ModuleId`：会重新引入「可被模块开关隐藏 / 排序」的语义，与「常驻且顺序固定」矛盾；又会让反向映射（模块 → 顶层 tab）与设置分类归属变复杂。下载页因此与设置一样映射为 `moduleOfHomeTab(...) => null`，只在 `homeActiveTabs` 里跟随浏览 / 下载能力的平台门禁出现或消失。
- 保留「下载页标题固定展开、不随滚动收起」：2026-11-07 用户要求下载页标题的 UI、样式与滚动行为都与浏览页一致（浮动标题胶囊、随滚动收放），该形态被取代；固定展开会让两个一级页面的标题行为不一致。
- 复用浏览页的浮动标题 / 视图页签外壳：下载页没有第二组视图，所以只复用浮动工具区骨架（标题胶囊 + 空动作槽），不搬入视图页签；页签会带来无意义的切换项。
- 在下载页启用统一任务浏览器：超出本次范围，且会改变现有任务卡片的操作与信息密度。

**Consequences**

- 导航顺序与常驻性不再受任何用户偏好影响；升级后旧顺序偏好与旧开关值对 Manga / 浏览 / 下载不再生效。平台门禁仍是唯一例外：iOS 等不允许下载能力的平台上，浏览与下载一起缺席。
- 桌面 ctl 的 `nav go downloads` 打开新下载页，`nav go browse` 仍打开浏览页；`nav list` 的可用页按 Manga → 浏览 → 下载 → 设置排序。
- 浏览页删除下载页签的全部状态、请求字段与页头 `resizeToAvoidBottomInset` 特例；浏览页本身的行为（在线源 / 发现 / 导入）不变。
- 下载页保活，会长期持有一份任务列表状态与数据库 watch 订阅；模块关闭 / 平台变化导致它从可见列表移除时，按既有保活剪枝逻辑 dispose。
- 下载页加入外壳的浮动工具区 tab 集合（`_tabHasFloatingChrome`），不再有「固定展开」判据（`homeTabPinsExpandedTitle` 已删除）。它的页内工具区条只画标题胶囊，不画视图页签。逐设计系统与浏览页一致：MD3 宽窗显示标题胶囊；MD3 窄窗不显示页面标题（标题在底部导航里）；Apple / 玻璃设计不画页内工具区，标题交给外壳大标题随滚动收起。
- 富任务浏览器仍是未接线代码；本次不清理它，也不把它接进下载页。
- 下载页与浏览页都受 ADR 0008 的 UI fidelity 约束：复用 Fushi v3.0.0 的组件、主题与布局语言，没有重设计任务卡片。

## Amendment 2026-11-09（manga-ux-batch）

一级导航修订为 **Manga → 浏览 → 历史 → 下载 → 设置**：新增的「历史」是不绑定模块的一级页，固定插在「浏览」与「下载」之间；「下载」仍是不绑定模块的一级页，现在固定跟在「历史」之后。历史与下载跟随同一条浏览平台门禁一起出现或消失（浏览缺席时两者都不出现）；Manga 与浏览仍常驻，设置仍恒在最后。本 ADR 原文的其余决策——下载迁出浏览页、页内浮动标题胶囊、列表留白读法、富任务浏览器不启用、UI fidelity——全部不变。

原 Consequences 中「Manga → 浏览 → 下载 → 设置」的顺序说明与 ctl 排序同步修订为：桌面 ctl 的 `nav go history` 打开历史页，`nav go downloads` 打开下载页，`nav go browse` 仍打开浏览页；`nav list` 的可用页按 Manga → 浏览 → 历史 → 下载 → 设置排序。
